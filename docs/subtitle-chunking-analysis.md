每条字幕为 `{start, end, text}`，时间单位是秒。条目对应短语，而非完整句子：

```text
10.70–13.48  嗯但这里面涉及到了很复杂的一个
13.48–14.36  智能体的流程
14.36–14.92  编排
```

字幕存在口语填充词、术语识别错误和跨条目的英文短语。保留原文和时间映射，
避免自动改写术语后把修改内容当成原始证据。

## Why it exists

现有实现按字幕条目聚合到约 600 字，保留约 100 字重叠及时间范围。
它保留来源，但不是按“完整句子”切分：本次样本没有句末标点。
约 73–93 秒的非末块可能覆盖多个讲解点，使局部检索和引用范围偏宽；
这是基于结构的判断，尚未通过检索评估证明效果下降。

逐条字幕太短，容易失去主语和上下文。仅按标点切分在本次样本上无效；
仅按停顿切分也无法使用，因为条间没有超过 2 秒的空隙。

## How to test or use it

建议 MVP 先尝试**按连续字幕条目聚合，结合字数与时长限制**：

1. 不拆普通字幕条目，从头按时间顺序累积。
2. 以约 300–500 字、45–75 秒作为候选目标，任一目标达到即在条目边界切分。
3. 字符数 600、时长 90 秒作为候选上限；异常超长单条需要单独处理，
   无词级时间戳时不得伪造精确定位。
4. 重叠保留末尾约 3–5 条字幕（时间约 6–12 秒），防止前提与结论跨块断开。
5. 若有可信章节或明显长停顿，可以提前切分；不要期待所有视频都有这些信号。
6. 块保留 BV、CID、字幕条目范围、原文和起止时间。

以上参数是待验证的起点，字数按字符计算，不等于模型 token 数。
对于当前视频推荐用途，先维持“视频摘要 + 字幕块”检索结构；
若小块缺少上下文，再评估命中块附带相邻块，暂不增加模型驱动的语义分块。

用相同真实字幕比较现有 600/100 字策略与候选策略，人工标注约 10–20 个
学习需求对应的证据时间段，比较 top-5 证据召回、理由是否有原文支持、
引用时间范围及向量/摘要调用成本。不同策略使用独立索引，避免影响推荐缓存。
未完成此对比前，不宣称候选参数最优。

若后续修改分块策略，索引缓存键需要包含策略版本；当前仅检查字幕内容和
Embedding 空间，单纯修改分块函数不会自动重建已有索引。
