# Embedding 语义切分实施计划

日期：2026-10-05。状态：已实施并通过本次样本验收；独立人审待完成。
实现与真实验证结果见 [语义切分验证](embedding-chunking-validation.md)。

## 目标与范围

将第 1 P 字幕从固定字数聚合改为 Embedding 语义切分：优先在明显语义变化附近
生成边界，同时保证每个输出 chunk 满足规定的长度范围。

本次只处理 chunk：字幕窗口构造、边界评分、长度约束、时间映射及分块测试。
复用现有 `EmbeddingModel` 适配层，不新增模型提供商或依赖。
字幕下载、搜索、用户记忆、推荐排序、摘要提示词、检索算法和 API 不属于本次任务。

## 范围定义与前提

以下作为可调整的实施假设，验收前必须固定：

| 项目 | 计划值 / 定义 |
| --- | --- |
| 最小长度 | 200 字符，包含边界值 |
| 最大长度 | 600 字符，包含边界值 |
| 字符计数 | `len(chunk.text)`，包括空格、标点和拼接换行；不是 token 数 |
| 语义分析窗口 | 切点左右各约 20 秒连续字幕，保留完整普通字幕条目 |
| 候选切点步长 | 约 4 秒，在对应字幕条目边界计算；首尾至少有 10 秒上下文 |
| 初始边界阈值 | 视频内语义距离的第 85 百分位，待样本验证 |
| 重叠 | 最多约 100 字符，仅在加入后仍满足最大长度时保留 |
| 时间戳 | 保留证据定位；本次不把 30–90 秒设为第二套硬约束 |

长度优先级高于语义偏好。不能为命中一个语义切点而产生短块或超长块。
若用户要求以秒数或 token 定义范围，应先修改本计划的参数和验收口径。

数学上不能保证任意输入都有合法划分：例如全文不足 200 字符。
对此返回明确的“无法满足 chunk 长度范围”错误，不填充、不重复正文凑长度，
不静默丢弃字幕，不返回违反范围的 chunk。空字幕返回空列表。
异常超长单条可以拆成连续文本片段，仍使用该条原始时间范围，不能声称词级定位。

## 当前问题

现有 `split_subtitles()` 约每 600 字切一次，最多约 100 字重叠，缺少最小长度约束。
真实字幕是短语而非完整句子，两个样本都没有句末标点；单条约 12–13 字。
固定聚合可能跨越多个讲解点，尾块也可能过短。

## 实施步骤

### 1. 建立可复现基线

- 选取已有成功下载的真实字幕，保存少量不含凭据的测试片段。
- 人工标注“问题背景→实现方案”“检索→生成”等明显变化的时间区间。
- 固定边界标签后再运行新策略，避免用结果反向定义正确答案。
- 先添加现有固定切分无法命中标注边界、无法保证尾块下限的回归测试。

### 2. 计算语义边界分数

- 保留字幕顺序、条目位置、原文和时间戳。
- 在每约 4 秒的候选边界两侧聚合各约 20 秒的小窗口，批量调用 `embedding.embed()`。
- 使用 `distance = 1 - cosine(left, right)` 衡量相邻窗口变化。
- 较大距离作为优先切点；阈值用于识别显著变化，不直接决定最终切分。
- 向量维度不一致、零范数或非法数值时明确失败；不伪装成成功的语义切分。
- 窗口不足两个时只使用长度约束，并记录无语义边界可比较。

### 3. 在合法范围内选择边界

- 在原始字幕条目边界上寻找合法划分；窗口边界提供语义优先级。
- 使用有长度上限的动态规划或等价的可行性检查，确保每次选择后，剩余文本
  仍存在合法划分，避免贪心切分留下短尾块。
- 在完整覆盖且所有块为 200–600 字符的方案中，优先选择显著语义变化位置；
  无显著变化时按长度选择，不强行把相对最高距离解释为主题变化。
- 尾块过短时移动之前的边界；合并会超上限时重新划分，不能仅拼到前一块。
- 先完成不重叠的合法划分，再按剩余容量加入前块尾部的完整字幕条目，
  不因重叠导致超长，不制造只含重复内容的块。
- 返回前逐块检查长度、来源和时间范围；任何不合法结果都不能发布。

### 4. 接入与文档

- 主要修改 `src/video_agent/rag.py`、`tests/test_rag.py`，按需增加专用分块测试。
- `Rag.index_video()` 传入已注入的 Embedding 接口；最终 chunk 单独计算索引向量，
  不用小窗口向量代替完整块向量。
- 缓存指纹包含分块策略版本、固定参数及 Embedding 空间，确保新策略不会复用旧块。
  这是分块生效所必需的调整，不扩展索引架构。
- 更新 `docs/rag.md`，记录 What was added、Why it exists、How to test or use it。
- 验证使用临时数据库，保留真实推荐库和已有每日清单。

## 验证与验收标准

### A. 明显语义变化

1. 确定性假向量测试：构造连续的主题 A、主题 B，预设跨主题距离明显较大，
   确认边界落在主题转换处，且覆盖全部字幕。
2. 真实模型测试：至少两个真实视频、累计至少 6 个预先标注的明显转换区间，
   输出距离曲线数据、实际切点及人工边界对照。
3. 对长度上可实现的标注转换，至少 80% 的区间内或距区间不超过一个分析窗口
   出现切点；这是本次项目验收目标，不是已验证的能力。
4. 被长度约束阻止的标注单独列明原因和实际切点，不计入可实现边界命中率；
   同时报告总标注数及受约束数，不能靠排除困难样本隐藏失败。
5. 检查稳定主题区间是否被过度切碎，记录长度强制切点与语义切点的区别。

### B. 长度范围与完整性

所有正常输出逐块满足 `200 <= len(text) <= 600`，不允许末块例外。
测试覆盖：

- 正好 200 / 600 字符，199 / 601 字符，换行计数及中文英文混排。
- 短尾块、合并后超长、多块重新平衡和重叠导致超长的情况。
- 全文过短、空字幕、异常超长单条和无法合法划分的输入。
- 全文无明显语义变化以及窗口很少的情况。
- 原文按顺序全部覆盖；除声明的重叠外不重复、不改写、不遗漏。
- BV/CID 正确，起止时间覆盖对应原始条目，块 ID 在相同输入下可复现。
